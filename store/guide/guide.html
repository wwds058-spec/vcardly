PART A · 5 MINUTES

Put your upload key into GitHub

The automatic build (CI) signs the Play Store file with your upload key. It reads the key from your repository's encrypted "Secrets", where nobody can see it, not even in the code.

  1. Open the private file VCardly-upload-key-PRIVATE.txt on your computer (any text editor, for example Notepad).
  2. In the browser, sign in to GitHub and open:
    OPEN THIS ADDRESShttps://github.com/wwds058-spec/vcardly/settings/secrets/actions
    (Or: your repository → Settings → left menu Secrets and variables → Actions.)
  3. Click New repository secret.
  4. In Name type exactly UPLOAD_KEYSTORE_BASE64. In Secret paste the long line under "1)" in the private file (it is one very long line; select all of it). Click Add secret.
  5. Click New repository secret again: Name UPLOAD_KEYSTORE_PASSWORD, Secret: the password from the private file. Add secret.
  6. Again: Name UPLOAD_KEY_ALIAS, Secret: vcardly-upload. Add secret.
  7. Again: Name UPLOAD_KEY_PASSWORD, Secret: the same password. Add secret.
Done whenThe Secrets page lists four names: UPLOAD_KEY_ALIAS, UPLOAD_KEY_PASSWORD, UPLOAD_KEYSTORE_BASE64, UPLOAD_KEYSTORE_PASSWORD. GitHub never shows the values again; that is normal.
Keep the key privateNever post the private file or the .jks file anywhere public, never put them in the code, never email them to anyone. Save a copy in a password manager or a private drive folder.
PART B · 10 MINUTES (AUTOMATIC)

Get the Play Store file (.aab)

Now that the key is in place, ask the automatic build to run once more. It makes the signed app bundle and puts it at a fixed download address.

  1. Open github.com/wwds058-spec/vcardly/actions.
  2. Click the newest run at the top of the list (named after the latest change).
  3. Top right: Re-run jobs → Re-run all jobs → confirm.
  4. Wait about 10 to 15 minutes until every job shows a green tick ✓ (build, instrumented, release, apk-arm64, ios).
  5. Download the bundle and its mapping file:
    APP BUNDLE (UPLOAD THIS TO PLAY)https://github.com/wwds058-spec/vcardly/raw/release-aab/vcardly-release.aab
    MAPPING FILE (UPLOAD LATER, PART G STEP 13)https://github.com/wwds058-spec/vcardly/raw/release-aab/mapping.txt
Done whenYou have vcardly-release.aab (about 25 to 45 MB) and mapping.txt on your computer.
If the release job is red, or the link says 404A secret name has a typo, or a value was not pasted completely. Check the four names in Part A (they must match exactly, all capitals), fix it with Update next to the secret, and re-run. If it still fails, send the red job's name to Claude.

Every later change to the app makes a new bundle at the same address with a higher versionCode, so for updates you just download again.

PART C · 10 MINUTES

Publish your privacy policy

Google requires a public web page with your privacy policy. It is already written (it matches exactly what the app does); you fill in three details and switch on free GitHub hosting.

C1. Fill in your details

  1. Open the privacy page file on GitHub.
  2. Click the pencil icon ✎ Edit this file (top right of the file).
  3. Press Ctrl+F (Cmd+F on Mac) to find and replace these three placeholders, including the square brackets:
    FindReplace with
    [YOUR NAME OR BUSINESS NAME]your name or your business name, e.g. Yasin Khan or Your Company Pvt Ltd
    [YOUR SUPPORT EMAIL]an email you read, shown publicly (a separate support address is a good idea)
    [DATE YOU PUBLISH]today's date, e.g. 10 October 2026
  4. Click Commit changes… → keep "Commit directly to the claude/happy-goodall-tjw9vc branch" → Commit changes.

C2. Switch on GitHub Pages (free hosting)

  1. Open github.com/wwds058-spec/vcardly/settings/pages.
  2. Under Build and deployment → Source: Deploy from a branch.
  3. Branch: choose claude/happy-goodall-tjw9vc, folder / (root) → Save.
  4. Wait 1 to 3 minutes, then open the page and check your name and email appear:
    YOUR PRIVACY POLICY ADDRESS (USED IN PART E)https://wwds058-spec.github.io/vcardly/site/privacy.html
Your repository is publicAnyone can see the app's code on GitHub. That is fine for publishing, and it is what makes free GitHub Pages work. Your key is safe because it is in Secrets, not in the code.

E7. Data safety (the longest form, take it slowly)

"Collected" means sent off the phone. VCardly sends no contacts, photos or notes anywhere. The only thing that leaves the phone is anonymous diagnostics from Google's text-recognition library (ML Kit): device model and how long reading a card took, never the image or the text.

  1. Start (or Manage). Read the overview → Next.
  2. Data collection and security:
    QuestionAnswer
    Does your app collect or share any of the required user data types?Yes
    Is all of the user data collected by your app encrypted in transit?Yes
    Which of the following methods of account creation does your app support?My app does not allow users to create an account
    (If asked) Do you provide a way for users to request that their data is deleted?No (there is no account or server data; everything stays on the phone and is deleted by "Erase all data" or uninstalling)
  3. Data types: tick only App info and performance → Diagnostics. Leave everything else (location, personal info, contacts, photos, financial, messages, device IDs…) unticked → Next.
  4. Data usage and handling → next to Diagnostics click Start:
    QuestionAnswer
    Is this data collected, shared, or both?Collected (not shared)
    Is this data processed ephemerally?No
    Is this data required for your app, or can users choose whether it's collected?Data collection is required
    Why is this user data collected?Analytics
    Save → Next.
  5. Check the Preview (it should say: no data shared; collects App info and performance) → Save → Submit if asked.
Contacts are not "collected"The app stores contacts and card photos only on the phone. Do not tick Contacts, Photos, Personal info or Location: Google's form is only about data that leaves the device.

PART G · 14 DAYS (MOSTLY WAITING)

Closed test: 12 testers for 14 days

Personal developer accounts created after 13 November 2023 must run a closed test with at least 12 testers who stay opted in for 14 days in a row before they can publish to everyone. Your Dashboard shows this requirement if it applies to you. (Organisation accounts can skip to Part H.)

G1. Collect 12 or more testers

Ask friends, family or colleagues with an Android phone for the Gmail / Google account email they use in the Play Store. Ask for 15 to 20, because some drop out, and the count must stay at 12 or more for 14 days.

G2. Create the closed test

  1. Left menu Test and release → Testing → Closed testing → on the "Closed testing - Alpha" track click Manage track.
  2. Tab Countries / regions → Add countries / regions → tick India (and any other countries your testers live in) → Add.
  3. Tab Testers → Create email list → List name VCardly testers → paste the emails (comma separated or one per line) → Save changes. Make sure the list is ticked.
  4. Feedback URL or email: your support email → Save.
  5. Still on Testers: find Join on the web or Copy link (the opt-in link). Copy it and keep it for G4.

G3. Upload the first release

  1. On the same track click Create new release.
  2. App integrity / Play App Signing: if asked, choose Use Google-generated key (recommended) → continue. Google keeps the app signing key safe; your upload key only signs uploads.
  3. App bundles: Upload → choose vcardly-release.aab from Part B. Wait until it shows 1.0.0 (versionCode …) with no errors.
  4. Release name: filled in automatically (e.g. 65 (1.0.0)); keep it.
  5. Release notes: paste the text from F4 between the <en-US> tags that are already there.
  6. Next (or "Save" then "Review release"). Read any warnings. Warnings in yellow are fine; red errors must be fixed (see Part J).
  7. Save and publish / Start rollout to Closed testing → confirm.
  8. Google reviews the first release: this takes from a few hours to about 7 days. You get an email; the status shows In review, then Available to testers.

G4. Let the testers in

  1. Once the release is available, send the testers the opt-in link from G2 step 5 with a short message, for example:
    MESSAGE TO TESTERS (EXAMPLE)Hi! Please help me test my new app VCardly. 1) Open this link on your Android phone, signed in with the Google account you gave me: [OPT-IN LINK]. 2) Tap "Become a tester". 3) Tap "Download it on Google Play" and install. Please keep it installed for at least 14 days, open it now and then, and tell me anything that goes wrong. Thank you!
  2. Watch Closed testing → Testers: it shows how many have opted in. It must reach 12 or more and stay there.

G5. Upload the mapping file (once per release)

  1. Left menu Test and release → Latest releases and bundles → App bundle explorer (or "App bundle explorer").
  2. Select the version you uploaded → tab Downloads → Assets → ReTrace mapping file / Deobfuscation file → Upload → choose mapping.txt from Part B.
WhyThe Play Store version is compressed and its code renamed to make it small. The mapping file lets Play Console show readable crash reports, which Claude can then fix.
PART H · AFTER 14 DAYS

Production: release to everyone

  1. After 14 days with 12+ testers, Dashboard shows Apply for production. Click it.
  2. Answer the questions about your test honestly, for example:
    Question (wording may vary)Example answer
    How did you recruit testers?Friends, family and colleagues who collect business cards.
    How easy was it to recruit?Choose the option that matches your experience.
    Describe the engagement you receivedTesters scanned their own visiting cards, saved contacts, set follow-up reminders and shared QR cards; they reported issues by message, which were fixed in updated test releases.
    What changes did you make based on testing?List real fixes, e.g. "Improved card edge detection on real photos; fixed the camera on some phones."
    Who is the intended audience?Professionals and small-business owners who exchange visiting cards and want to keep contacts organised and private on their phone.
    How does the app provide value?Turns paper visiting cards into contacts in seconds, reminds users to follow up, and keeps everything on the phone without an account.
    Expected installs in the first yearChoose a realistic range (e.g. 0 – 10K).
  3. Submit. Google answers by email, usually within 7 days.
  4. When approved: left menu Test and release → Production → tab Countries / regions → add India (or Add all) → Save.
  5. Create new release → Add from library → pick the bundle already tested (or upload the newest .aab from Part B) → release notes (F4) → Next.
  6. Staged rollout: set 20% to start (only a part of users get it first, so a problem affects few people). Save and publish.
  7. After a few days with no crashes (left menu Monitor and improve → Android vitals → Crashes and ANRs), open the release and click Increase rollout → 100%.
Done whenThe app's store page is live at play.google.com/store/apps/details?id=com.yasin.vcardly and anyone can install it.
PART I

Updating the app later

  1. Ask Claude for the change. Every change is pushed to GitHub and the automatic build makes a new bundle with a higher versionCode.
  2. When all checks are green, download the new vcardly-release.aab and mapping.txt (same links as Part B).
  3. Play Console → the track (Closed testing or Production) → Create new release → upload → release notes describing what changed → Save and publish.
  4. Upload the new mapping.txt to that version (Part G5).
  5. For a new user-visible version number (e.g. 1.1.0), ask Claude to change versionName.

Switching on ads or VCardly Pro (optional, later)

This first version is completely free with no ads. If you later want income, ask Claude to switch on AdMob ads (needs an AdMob account) and/or VCardly Pro (create two products in Play Console: vcardly_pro_lifetime and vcardly_pro_yearly). Then the answers in E3 (Ads), E6 (Advertising ID), E7 (Data safety), the description and the privacy policy must be updated in the same update; Claude prepares all of them.

PART J

Problems and how to fix them

Message or problemWhat to do
"Version code … has already been used"You uploaded the same bundle twice. Download the newest one (Part B), or ask Claude to trigger a new build.
"Your app must target Android 16 (API level 36)"Already done (VCardly targets API 36). If it ever appears for a later year, ask Claude to raise it.
"The Android App Bundle was not signed" / "signed with the wrong key"Check the four GitHub secrets (Part A). Use only bundles from the release-aab link. If you ever lose the key: Play Console → Setup → App signing → Request upload key reset.
Privacy policy URL "invalid" or "not reachable"Open it in a browser; if it shows 404, re-check GitHub Pages (Part C2) and wait a few minutes.
Advertising ID warningAnswer "No" in E6; this build has no advertising permission (the automatic build checks it every time).
"You need at least 12 testers"Add more emails to the tester list and make sure each person opened the opt-in link and tapped "Become a tester".
Testers cannot find the appThey must use the same Google account on the phone as the email you added, open the opt-in link first, and their country must be in the track's countries.
Release rejected for "Policy" reasonsRead the email from Google; send the exact text to Claude. Most are fixed by changing a listing text or an App content answer.
Crashes in Android vitalsMake sure mapping.txt is uploaded (G5), then send Claude a screenshot of the crash.
